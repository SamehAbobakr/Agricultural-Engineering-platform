# نظام الإعلانات — قاعدة البيانات

| الملف | ماذا يفعل |
|---|---|
| `001_announcements.sql` | جدول `announcements` + القيود + الفهارس + trigger (إعلان نشط واحد) + سياسات RLS |
| `002_announcements_copy_text.sql` | يستبدل القيد `announcements_button_pair` ليسمح بزر نسخ (`button_text` + `copy_text`) بلا رابط. **نفّذه بعد إضافة عمود `copy_text`** |
| `tests/announcements_tests.sql` | اختبار على **Staging** يعمل داخل Transaction وينتهي بـ `ROLLBACK` (لا يترك أثرًا) |

## التنفيذ (يدويًا من Supabase → SQL Editor)
1. تأكد أن `database/admin/001_admin_setup.sql` نُفِّذ من قبل (يوفّر `public.is_admin()`).
2. نفّذ `001_announcements.sql` على **Staging** أولًا ثم Production (آمن لإعادة التشغيل، لا يحذف بيانات).
3. (موصى به) شغّل `tests/announcements_tests.sql` على Staging: يجب أن تظهر `PASS 1` … `PASS 10` بلا أي `FAIL`.

## كيف تنشر أول إعلان
1. سجّل دخولك بحساب المسؤول ← لوحة الإدارة ← **إدارة الإعلانات** (مجموعة «النظام»).
2. اضغط **＋ إضافة إعلان**، واملأ العنوان والنص والنوع (الصورة والزر اختياريان؛ الزر يحتاج نصًّا ورابطًا معًا).
3. اضغط **معاينة** لترى الإعلان كما سيظهر للطلاب، ثم فعّل «نشط» واضغط **إضافة**.
4. افتح الصفحة الرئيسية في نافذة خاصة (جلسة جديدة) لترى النافذة.

لتعطيله: من القائمة اضغط **تفعيل / تعطيل**. لاستبداله: فعّل إعلانًا آخر (يُطلب تأكيد، ويُعطَّل السابق تلقائيًا ويبقى محفوظًا).

## قواعد السلوك
| الحالة | النتيجة |
|---|---|
| لا إعلان نشط / الإعلان معطّل | لا تظهر أي نافذة |
| إغلاق الطالب للنافذة | تُخفى في جلسة التصفح الحالية فقط (`sessionStorage`)، والإعلان يبقى نشطًا في القاعدة |
| جلسة تصفح جديدة | يظهر الإعلان النشط مجددًا |
| تفعيل إعلان جديد | يُعطَّل النشط السابق تلقائيًا (لا حذف) ويظهر الجديد حتى لمن أغلق القديم |
| فشل الاتصال / الجدول غير منفَّذ | لا نافذة ولا تأثير على بقية المنصة (تحذير في Console فقط) |

## سياسات RLS
| السياسة | الأدوار | العملية | الشرط |
|---|---|---|---|
| `announcements_public_read` | anon, authenticated | SELECT | `is_active` (النشط فقط) |
| `admin_all` | authenticated | ALL | `is_admin()` (قراءة الكل + إضافة/تعديل/تفعيل/حذف) |

الزائر لا يملك صلاحية INSERT/UPDATE/DELETE أصلًا (`GRANT SELECT` فقط). لا تعديل على أي جدول أو سياسة قائمة، ولا مفتاح `service_role` في الواجهة.

## ضمان «إعلان نشط واحد»
1. فهرس فريد جزئي: `UNIQUE (is_active) WHERE is_active` → يستحيل وجود نشطين معًا.
2. trigger قبل الكتابة يعطّل النشط السابق (UPDATE فقط) ويستخدم `pg_advisory_xact_lock` لمنع تعارض تفعيلين متزامنين.

## أين تظهر النافذة؟
في الصفحة الرئيسية `index.html` فقط (سطران: `css/announcements.css` و`js/announcements.js` مع `data-auto`). لعرضها في صفحة أخرى أضف السطرين نفسهما فيها.


## زر النسخ (copy_text)
| الحالة | سلوك الزر |
|---|---|
| `copy_text` غير فارغ | زر نسخ (نصه `button_text`، وإن غاب «نسخ») ولا يُفتح أي رابط، حتى لو وُجد `button_url` |
| `copy_text` فارغ و`button_url` موجود | رابط عادي كما كان |
| كلاهما فارغ | لا زر |

القيد الجديد: الرابط يحتاج `button_text`، و`button_text` يحتاج رابطًا أو `copy_text` غير فارغ.
